# Sotto on iOS and Android

The mobile apps use the same Rust engine and vault as the desktop app through UniFFI bindings in [`bindings/`](bindings), generated by `scripts/mobile-bindings.sh` from `crates/sotto-ffi`.

## What the bindings provide

- `SottoClient(dataDir, relay, socks)`: `setup`, `unlock`, `lock`, `panicWipe`, `state`
- Conversations: `contactsJson`, `messagesJson`, `sendText`, `createInvite`, `acceptInvite`, `markVerified`
- `setListener(EventListener)`: live events (the same JSON the desktop agent streams), so screens update as messages arrive
- Helpers: `generateCodename`, `safetyNumber`, `inspectInvite` (show who an invite is from before accepting)

## Building the native apps

This repository's build machine has no Xcode or Android SDK, so the native app shells are not part of this build. To integrate:

- **iOS**: build `sotto-ffi` as a static library for `aarch64-apple-ios` and `aarch64-apple-ios-sim`, wrap it in an XCFramework, add `bindings/sotto_ffi.swift` and the `sotto_ffiFFI` module map. Use Tor for iOS (or the Orbot iOS VPN) and pass its SOCKS address.
- **Android**: build with `cargo ndk -t arm64-v8a -t x86_64`, add the `.so` files under `jniLibs`, add `bindings/uniffi/sotto_ffi/sotto_ffi.kt` and the JNA dependency. Use Orbot or an embedded tor and pass its SOCKS address.

Platform rules from the spec still apply: store the vault under app-private storage, block screenshots (`FLAG_SECURE`, iOS hidden-content on capture), never show sender or content in notifications, and keep safe review on the desktop app (High risk and Extreme modes).
